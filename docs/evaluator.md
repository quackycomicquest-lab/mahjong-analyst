# 判断評価エンジン（仕様 §3, §4-1 ③）

> v0.2.0：打牌に加えて、鳴き（ポン・チー・大明槓・スキップ）、和了（ロン・ツモ）、カン（暗槓・加槓）、九種九牌も評価する。
> 定数は AI 同士の 8,000 半荘で実測した値に置き換えた（[calibration.md](calibration.md)）。
>
> | 判断 | 比べる候補 |
> |---|---|
> | 打牌 | 全ての打牌（立直できる牌は立直・ダマの両方）。立直判断の欄で同じ牌の立直とダマを比較 |
> | 鳴き | スキップ／ポン・チー（鳴いた後に切る牌の上位3候補まで試し、最善のもの）／大明槓（嶺上牌をツモる） |
> | 和了 | ロン・ツモ（確定した和了点）と、見逃して続けた場合 |
> | カン | カン（嶺上牌をツモる。新ドラは未考慮のため暫定）と、カンしない打牌 |
> | 九種九牌 | 流局（収支0）と、続ける打牌 |

コード：`src/engine/evaluator/`（`evaluate.ts` 評価・解説、`simulate.ts` 期待値シミュレーション、`types.ts` 結果の型）
バージョン：`evaluator-0.1.0`（評価結果に記録される）

## 使い方

```ts
const view = getPlayerView(game, 0)          // 打牌確定時点のスナップショット
const evaluation = evaluateDecision(view, action, { mode: 'full' }) // iPhone は 'light'
```

- 入力はプレイヤー視点（`PlayerView`）だけ。他家の手牌・山・裏ドラは使わない（仕様 §4-1）。
- `evaluation.decisionId` が局面IDで、古い評価が別の局面に表示されないよう突き合わせに使う（仕様 §5-3）。
- 打牌（立直宣言を含む）以外の行動は `status: 'unavailable'`、点数は `null`（根拠のない点数を作らない、仕様 §3-3）。

## 評価の仕組み

1. 合法な打牌候補をすべて挙げる（同じ種類・同じ赤・同じ立直有無は1つにまとめる）。
2. 候補ごとに、この局の残りを見えていない牌の並べ替えで繰り返しシミュレーションし、**この局の収支の期待値**を出す。全候補で同じ乱数列を使い、候補間の差を比べやすくしている。
   - 自分の打ち方：有効牌を引けば向聴数が最も進む打牌（聴牌に取るときはフリテンにならない待ちを優先）。有効牌でなくても、ツモ牌の方が手の中で最も孤立した牌より役立つなら入れ替える。他家の捨て牌は、向聴数が進み役（役牌・対々和・断幺九・混一色）の見込みがあればポン・チーする（役牌のポン以外は鳴いた後が2向聴以内、チーは上家だけ、間の打ち手を飛ばして手番が進む）。脅威があり2向聴以上なら最も安全な牌で降りる。門前で聴牌したら立直（打牌時点で聴牌の候補は、選んだ立直・ダマのまま）。
   - 他家：打牌ごとに一定確率で他家同士の和了により局が終わる（立直者がいると上がる、自分が立直すると下がる）。他家の打牌が当たり牌でも、実際に切られる割合を掛ける（ダマ0.45、立直0.25）。
   - 放銃：危険度推定（現物・スジ・字牌・壁・ワンチャンス）から打牌ごとの放銃確率と失点を掛ける。
   - 収支に含めるもの：和了点（立直時は裏ドラ・一発の期待分として1.2倍）、放銃、流局時の聴牌料／ノーテン罰符の目安、立直棒。
3. **判断損失** = 最善候補の期待値 − 選んだ打牌の期待値（点）。評価点とは別に保持する。
4. **評価点** = `100 × exp(−(判断損失 − 誤差) / 尺度)`。尺度は「最善候補と候補全体の中央値との期待値差」（120〜1000点）で、その局面で判断がどれだけ点数を左右するかに合わせた相対値。誤差の範囲内の差は減点しない。
5. **状態**：脅威（立直・2副露以上）がある局面は、危険度が経験則による推定なので `provisional`（暫定評価）。誤差が大きいときも暫定。

## 表示項目との対応（仕様 §3-2）

| レベル | 項目 | フィールド |
|---|---|---|
| 1 | 評価点・最善候補・評価差・良かった点・改善点 | `score` `best` `loss` `good` `improve` |
| 2 | シャンテン数・受け入れ枚数・有効牌・打点期待値・和了期待値・放銃リスク | `chosen.shanten` `ukeire` `effectiveKinds` `winValue` `winRate` `immediateDealIn` `dealInRate` |
| 3 | 押し引き・相手の立直への対応・安全牌選択・局面全体の期待値 | `analysis.stance` `analysis.threats` `analysis.safest` `candidates[].ev` |
| 3 | 順位期待値 | `analysis.rankExpectation`（**未対応**、常に null） |

保存用の記録は `EvaluationRecord`（スナップショット・実際の行動・評価結果・日時）。全候補の評価、信頼度、エンジンのバージョン、所要時間、判断損失を含む（仕様 §3-4）。

## 処理時間（Mac / Node、`npm run eval-timing`、実際の対局120局面）

| モード | 試行回数/候補 | 中央値 | 90% | 最大 |
|---|---|---|---|---|
| full（Mac） | 400 | 126ms | 261ms | 331ms |
| light（iPhone 想定） | 100 | 31ms | 65ms | 72ms |

（シミュレーションに鳴き・形の改善・フリテン回避を入れた後の値。入れる前は full 50ms・light 13ms）

iPhone 実機では未計測。Web Worker で動かす前提なので、対局の操作は止めない（仕様 §5-3）。

## 例（`npm run eval-demo`）

- 仕様 §3-1 の手牌（1〜6萬 2〜5筒 78索 東東）で東を切る → **29点**、最善は2筒（聴牌）。「向聴数が戻る選択です」。
- 3向聴の手で両面を崩す → 47点。
- 立直者に対して4向聴の手で東を切る → 78点（暫定）、最善は現物の5萬（降り）。
- 役なし両面聴牌でダマ → 立直が最善。

## 分かっている限界

- 他家の手は「見えていない牌の一様な並び」として扱う。相手の手役や聴牌気配は読まない。
- ダマで待ちを良くしてから立直する、といった途中の判断の切り替えはシミュレーションに入っていない。そのため役なし嵌張聴牌の立直とダマは誤差の範囲の差になる。
- 鳴き・槓・見逃しの評価、順位期待値は未対応。
- 定数（他家の和了確率、当たり牌が出る割合、立直の効果など）は実戦の傾向に合わせた目安で、今後の検証で調整する。
