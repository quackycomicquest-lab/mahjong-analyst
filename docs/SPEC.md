## 0. 確定方針

| 項目 | 決定 |
|---|---|
| 対局 | 自分1人 ＋ AIプレイヤー3人 |
| AI評価 | 自分の打牌を**確定した後**に評価を表示 |
| 対応端末 | Mac・iPhone |
| 目的 | 麻雀の実力向上に特化 |
| 対局形式 | 四人打ち日本式リーチ麻雀 |
| 利用形態 | 個人利用前提のPWA |

- 中心は「自分で考えて打牌 → AIから答え合わせ」の学習サイクル。AIが打牌を指示するアプリではない。
- 画面設計・AIエンジン・データ保存を分離し、端末ごとの性能差を吸収する。

## 1. プロダクト定義

### 1-1. 概要
麻雀AIを活用し、対局・評価・分析・復習を一体化した個人用麻雀トレーニングシステム。

| 柱 | 内容 |
|---|---|
| 判断力の向上 | 自分の判断をAIで検証 |
| 実力の可視化 | 判断の質を定量分析 |
| 復習の蓄積 | 過去の局面を再検討 |
| 弱点の改善 | 苦手な判断を重点練習 |

### 1-2. 基本フロー
【欠落】フロー図。

- AI評価の**表示**は打牌確定後。
- AIが**評価する対象**は打牌直前の局面。未来の情報を使わず、その時点の判断を公平に評価する。

## 3. AI評価システム仕様（最重点）

### 3-1. 評価処理のタイミング
説明用の仮想例：

- 打牌前手牌：1萬 2萬 3萬 4萬 5萬 6萬 2筒 3筒 4筒 5筒 7索 8索 東 東
- 自分の打牌：東
- 事後評価：**92 / 100**「最善候補と比較して、わずかに期待値が低い選択でした。」

打牌確定時点で、直前の手牌・局面を**スナップショット**として保存し、AIに渡す。

### 3-2. 評価パネル（3段階）
初期表示はレベル1。詳細は展開で表示。

| レベル | 項目 |
|---|---|
| 1 簡易評価 | 評価点／最善候補／自分の打牌との評価差／良かった点・改善点 |
| 2 詳細評価 | シャンテン数／受け入れ枚数／有効牌の種類／打点期待値／和了期待値／放銃リスク |
| 3 専門分析 | 押し引き判断／相手リーチへの対応／安全牌選択／順位期待値／局面全体の期待値変化 |

### 3-3. 評価点の算出
- 表示用評価点は100点満点。
- 【欠落】内部で別々に管理する値の表。
- 内部値を無理に単純加算しない。最終評価点は**AIが算出した期待値差を基準に相対変換**する。
- **判断損失**は評価点とは別に保持する。
- 期待値が十分に計算できない場合は「評価不能」「暫定評価」と表示し、根拠のない点数を作らない。

### 3-4. 評価結果の履歴
全打牌について保存：打牌前の局面／実際の打牌／AI最善候補／全候補の評価／AI評価の信頼度／評価エンジンのバージョン／評価所要時間／判断損失。
→ 後から過去の打牌を再評価できるようにする。

## 4. AIエンジン実装仕様

### 4-1. エンジンの分離

| # | モジュール | 責務 |
|---|---|---|
| ① | Mahjong Rules Engine | ルール処理・牌管理・シャンテン数・和了判定・点数計算・鳴き判定 |
| ② | Mahjong Player AI | AI3人の打牌選択・リーチ判断・鳴き判断・押し引き |
| ③ | Mahjong Evaluator | 人間の打牌評価・全候補比較・期待値算出・放銃リスク・最善手判定 |
| ④ | Mahjong Coach | 判断ミス分類・解説生成・成績分析・復習問題作成 |

- ②と③は同じAIエンジンを利用し得るが、**役割と入力情報は分離**する。
- **③には相手の隠し手牌を渡さない。**

### 4-2. AIエンジン候補の検証方針
【欠落】候補表。現段階では採用を確定しない。同一局面を各エンジンに入力し、以下を比較する：
推奨打牌の一致率／評価結果の妥当性／推論時間／Macでの動作／iPhoneでの動作／商用利用条件・ライセンス／隠し情報を使用しない評価が可能か。
Mortal・Akochan等の既存AIも、内部の評価仕様と実行方法を調査してから採用する。
→ 調査結果：[phase0-engine-evaluation.md](phase0-engine-evaluation.md)

### 4-3. 端末ごとのAI実行方式
- AIエンジンには共通インターフェースを用意する。【欠落】インターフェース定義
- 推奨構成：TypeScript（基本ルール・牌効率）／WebAssembly（高負荷計算）／Web Worker（バックグラウンドAI計算）／IndexedDB（対局履歴）／必要に応じONNX Runtime Web等を検証。
- MacとiPhoneで評価品質が極端に変わらないようにする。重い評価ができない場合は簡易評価に切り替え、**評価の種類と精度を明示**する。

## 7. 成績分析・学習システム

### 7-1. 成績指標
【欠落】指標表。
- **AI一致率をそのまま実力スコアにしない**（最善手と異なっても期待値がほぼ同じなら悪手ではない）。

### 7-2. 弱点の分類
牌効率／打点構築／リーチ判断／押し引き／ベタオリ／安全牌選択／鳴き判断／オーラスの順位判断。
各分類を **直近10半荘・直近30半荘・累計** で比較できるようにする。

### 7-3. 復習機能
【欠落】機能表。
- 復習問題は実際の対局から抽出。
- 以前間違えた局面を一定期間後に再出題する（間隔反復）。

### 7-4. 追加提案：5能力値
平均順位とは別に、判断能力そのものの改善を追跡する。
牌効率能力／攻撃判断能力／守備判断能力／押し引き能力／順位戦略能力
