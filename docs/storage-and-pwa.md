# 履歴保存とオフライン対応（仕様 §3-4, §6, §10-2）

## 保存（IndexedDB）

コード：`src/storage/db.ts`。データベース名 `mahjong-analyst`、バージョン 1。端末の中だけに保存し、ログインやクラウド同期はしない（仕様 §5-1）。

| ストア | キー | 1件の中身 | 書き込むタイミング |
|---|---|---|---|
| `games` | `id` | seed、全行動、設定、参加者名、最後の局、結果、集計（評価した打牌数・平均点・判断損失の合計） | 行動のたび（0.4秒まとめて） |
| `evaluations` | `[gameId, decisionId]` | 打牌直前の局面スナップショット（`PlayerView`）、実際の打牌、評価結果（全候補・信頼度・エンジンのバージョン・所要時間・判断損失）、局名、日時 | 評価が終わったとき |

- 対局は「seed＋全行動」から `MahjongGame.replay` で完全に再現できるので、局面そのものは保存しない。アプリを閉じても、タイトルの「続きから」で同じ局面に戻れる。
- 評価記録には局面スナップショットを保存しているので、評価エンジンを改良した後に過去の打牌を再評価できる（仕様 §3-4）。
- 保存に失敗しても（プライベートブラウズなど）対局は続けられ、画面上部に「保存できませんでした」と表示する。
- 1半荘あたりの容量は、評価記録を含めて数百KB〜1MB程度の見込み。

## 画面

- タイトル：「続きから」（最も新しい未終了の対局）、「対局履歴・振り返り」
- 対局履歴：日時・形式・AIの強さ・順位と点数（中断中なら局名）・打牌評価の平均点
- 振り返り：局ごとの打牌一覧（点数の色分け、70点未満だけの絞り込み）。打牌を選ぶと、そのときの手牌（自分の打牌と最善の打牌に印）と評価の詳細を表示

## オフライン対応（PWA）

- `public/manifest.webmanifest`：アプリ名、アイコン（192・512・iPhone用180）、全画面表示
- `vite.config.ts` の `serviceWorker()`：ビルド時に `dist/sw.js` を生成し、出力される全ファイル（画面・JS・CSS・評価 Worker・アイコン）を事前キャッシュする。ファイルの構成が変わるとキャッシュ名が変わり、古いキャッシュは消える
- 画面（HTML）はネット優先・つながらなければキャッシュ、JS・CSS・画像はキャッシュ優先
- 開発サーバー（`npm run dev`）では Service Worker を登録しない

確認済み：本番ビルドを配信 → 一度開く → サーバーを止める → 再読み込みしても起動し、対局・打牌評価まで動く（Mac のブラウザ）。

## 公開と iPhone での使い方

公開先：**https://quackycomicquest-lab.github.io/mahjong-analyst/**（GitHub Pages）

- `main` ブランチに push すると、GitHub Actions（`.github/workflows/deploy.yml`）がテスト → ビルド（`BASE_PATH=/mahjong-analyst/`）→ 公開まで自動で行う。テストが失敗したら公開されない。
- 公開URLは知っている人なら誰でも開けるが、対局データは各端末の IndexedDB にだけ保存され、サーバーには送られない。

iPhone のホーム画面に追加する手順：

1. iPhone の Safari で公開URLを開く（一度開くとオフライン用のキャッシュが作られる）
2. 共有ボタン →「ホーム画面に追加」
3. ホーム画面のアイコン（麻雀分析）から起動すると、全画面のアプリとして動き、機内モードでも対局と評価ができる

注意：Service Worker（オフライン動作）は HTTPS のページでしか動かない（`localhost` は例外）。Mac の開発サーバーに iPhone から `http://192.168.x.x:5173` でつなぐと対局はできるが、オフラインにはならない。

ローカルで公開時と同じ形を確かめるには：

```bash
BASE_PATH=/mahjong-analyst/ npm run build
npx vite preview --base /mahjong-analyst/
```
